allowed-tools: Bash(git:*)
description: Prepare good commit message.
---

Prepare a good descriptive commit message.
Read what is actually staged in git index.
Use conventional commits.
Do not be too verbose. Don't say the tests pass, this is obvious.
Avoid all obvious stuff.
Make sure unreleased changelog file is updated.
Do not push the changes.

You're authorized to commit exactly once, and you will need to wait for the user to ask
again explicitely before you can do any other commit.
