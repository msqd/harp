Dashboard authentication accepts only the ``pbkdf2_sha256`` (default), ``argon2`` (extra) and ``plaintext`` (tests only, ``plain`` still an alias) algorithms; passlib is removed and existing ``pbkdf2_sha256`` hashes keep working at their cost until rehashed (new ones use 600000 rounds instead of 29000). Configurations on any other passlib algorithm (``bcrypt``, ``md5_crypt``, ...) refuse to start. Every check now costs the costliest configured hash, whether the user is known, unknown or malformed, and verifications run on a dedicated pool of 4 threads. See :ref:`upgrading-0-13`.
