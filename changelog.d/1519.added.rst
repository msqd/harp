Add the ``auth`` application: the ``users`` table becomes ``auth_accounts``, accounts hold a ``viewer``, ``editor`` or ``admin`` role that every dashboard route enforces (403 below it), requests resolve to one actor context, and ``harp-proxy auth:create-account``, ``auth:set-role``, ``auth:disable-account`` and ``auth:enable-account`` manage accounts. The Basic users of the configuration are imported once, existing accounts are migrated disabled. Applications now bring the applications they depend on, so a list that names the dashboard loads ``auth``. The dashboard now requires ``auth`` and shows the account and role in its header. SQLite files from earlier versions are recreated. (#1519)
