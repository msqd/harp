The HTTP cache keeps indexed records, one per resource and one per ``Vary`` variant, in the ``http_cache_*`` tables of the storage database (PostgreSQL, SQLite) or in memory, with its bodies stored once by content digest and per-endpoint counters kept on write. The existing cache is dropped once at upgrade: the cache starts empty, and the janitor deletes the old ``cache/meta`` blobs. With Redis as blob storage, the cache is now in the storage database. The cache key is the endpoint and path, then a hash of the query string, so no query value is stored; responses to URLs with a redacted query parameter are now cached.
