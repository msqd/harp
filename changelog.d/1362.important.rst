New default stack: ``hypercorn`` on ``uvloop`` (``--server hypercorn+uvloop``) and the aiohttp upstream transport (``http_client.transport.type: harp_apps.http_client.aiohttp_transport.AiohttpTransport``). On Windows, where uvloop does not exist, the asyncio loop is used (with a warning if a uvloop server is asked for). The aiohttp transport trusts certifi for ``verify: true`` like httpx, and refuses at startup what it cannot honour, naming ``httpx.AsyncHTTPTransport`` as the way out: ``retries`` above 0, ``verify`` as a CA path, ``limits.max_keepalive_connections``, ``http1: false``, ``http2``, ``cert``, ``proxy``, ``uds``, ``local_address``, ``socket_options`` and ``trust_env``. The ``write`` timeout is not applied and responses always report HTTP/1.1. To restore the previous stack, set ``http_client.transport.type: httpx.AsyncHTTPTransport`` and run with ``--server hypercorn`` (or ``HARP_SERVER=hypercorn``).
