Rules now match ``/api//admin``, ``/admin;x=1`` and ``/admin%2Fusers`` like the clean path (empty segments and ``;`` parameters are dropped, a final slash is kept once, ``%2F`` also matches as ``/``), so deny rules hold for the variants upstreams normalise; the forwarded path is unchanged. Known limits: double-encoded escapes, ``%3B``, ``%00``, ``%5C`` and backslashes, case differences and upstream-specific rewriting are not normalised, ``on_remote_*`` levels still match the raw path, a pattern containing ``//`` or ``;`` no longer matches, ``GET /admin`` does not match ``/admin/`` (write ``GET /admin*``), and a non-deny rule for ``GET /a/b`` also fires for ``/a%2Fb``.
